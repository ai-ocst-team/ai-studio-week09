# 3.6 AI·데이터 보안 체크리스트


| 구분 | 번호 | 점검 항목 | 확인 | 점검 및 조치 결과 |
|:---:|:---:|---|:---:|---|
| 데이터 | S1 | 제출물에 실존 인물의 실명·전화번호·이메일 등 PII가 포함되지 않았다 (더미 데이터 사용). | ☑ | `validate_vlm_response`의 공개된 테스트 예시는 가상 점수·태그를 사용함. |
| 데이터 | S2 | 외부 AI(챗봇·API)에 기업 기밀·타인 코드·PII를 입력하지 않았다. | ☑ | Copilot으로 생성했으며 프롬프트·코드 기록이 존재함.|
| 데이터 | S3 | 외부 데이터 사용 시 출처·라이선스를 확인하고 PII 열을 비식별 처리했다. | ☑ | 별도 외부 데이터셋을 요구하지 않음. |
| 키 관리 | S4 | API 키·비밀번호가 소스코드에 하드코딩되어 있지 않다. | ☑ | 공개된 `validate_vlm_response` 코드에는 API 키를 직접 사용하지 않음.|
| 키 관리 | S5 | `.env` 파일이 `.gitignore`에 등록되어 있고, `git ls-files` 확인 결과 추적되지 않는다. | ☑ | 프로젝트 최상위 폴더에서 실행. |
| 키 관리 | S6 | 커밋 히스토리에 키가 노출된 적이 없다 (노출 시 폐기·재발급 완료를 명기). | ☑음| 해당없음. |
| 키 관리 | S7 | 키·비밀 값을 print/log/스크린샷으로 전체 출력하지 않았다. | ☑ | 해당없음. |
| AI 사용 | S8 | AI 사용 내역(프롬프트·채택·수정)을 과제 규정에 따라 기록·첨부했다. | ☑ | `validate_vlm_response`에 대해 `prompt_log.md` 작성|
| AI 사용 | S9 | (LLM 기능 포함 시) 사용자 입력 검증과 출력 검증(형식 확인)을 적용했다. | ☑ | VLM 응답의 JSON 형식·필수 필드·점수 범위·허용 태그·초점 상태를 검증하고 부적합 시 `ValueError` 발생. |
| AI 사용 | S10 | (LLM 기능 포함 시) 시스템 프롬프트에 비밀 정보를 포함하지 않았다. | ☑ | 해당없음. |
