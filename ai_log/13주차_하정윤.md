## [2026-11-27] 파이프라인 예외 분기 분리(`RuntimeError` vs `ValueError`) 및 SDK 재시도·설정 우선순위 검증 (담당: 하정윤)
- **대상 모듈**: `llm_service.py`, `analyze_with_gemini/llm_client.py`, `tests/test_llm_service.py`, `tests/test_llm_client.py` / **관련 커밋**: `[커밋 후 기입]`
- **품질 관점**: [예외 경계 설계 · 설정 격리 · SDK 호환성]
- **설계 검토 및 발견한 문제**:  
  1. **[`pipeline.py`와의 예외 충돌 위험]**: 기존 `pipeline.py`와 13주차 `backend.evaluate_uploaded_photos` 설계에서는 이미지 손상 등 개별 파일 오류(`ValueError`, `OSError`)만 실패 목록으로 삼키고 계속 진행하며, API 키 누락·인증·한도 오류는 즉시 중단/전파해야 함. `ANTHROPIC_API_KEY` 미설정을 `ValueError`로 던지면 파이프라인이 설정 오류를 개별 이미지 오류로 오인해 삼킬 위험이 있었음.
  2. **[`.env` 오염 방지 및 SDK `httpx2` 예외 생성자 차이]**: `dotenv.load_dotenv()`는 프로세스 `os.environ`을 변경해 `pytest` 간 설정 격리를 깨뜨릴 수 있었고, 로컬 환경의 `anthropic 2.14.0`은 내부 HTTP 객체로 `httpx` 대신 `httpx2`를 사용해 단위 테스트에서 `RateLimitError`/`APITimeoutError` 구성 시 시그니처 불일치 오류가 확인됨.
- **수정 및 구현 내역**:  
  1. API 키 미설정 시 `RuntimeError`를 발생시켜 `pipeline.py` / `evaluate_uploaded_photos`의 이미지 `ValueError` 예외 처리와 명확히 분리함.
  2. 설정 조회 시 `dotenv.dotenv_values(_ENV_PATH)`로 읽기 전용 조회만 수행해 `os.environ` → `st.secrets`(지연 조회) → `.env` → 기본값 순서를 유지하면서도 환경 오염을 차단함(OS 빈 문자열 `""` 보존 포함).
  3. `max_retries=0`으로 SDK 내부 재시도를 끄고 `_call_messages_create()`에서 `(anthropic.RateLimitError, anthropic.APITimeoutError)`만 `[1, 2, 4]`초 백오프로 재시도하며 `AuthenticationError`는 1회 즉시 전파하도록 구현·테스트(`httpx2`/`httpx` 양립 헬퍼 적용).
