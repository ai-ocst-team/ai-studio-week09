## [2026-11-16] CSV 최초 읽기 전 파일 포인터 방어 및 Streamlit 폐기 API 제거 (담당: 하정윤)
- **대상 모듈**: `app.py` / **관련 커밋**: `e31898f` → `e271579`
- **품질 관점**: [안정성 · API 호환성]
- **초기 프롬프트 (요지)**:  
  "업로드된 CSV를 읽을 때 UTF-8 실패 시 `seek(0)` 후 CP949로 재시도하고, 상세 분석 목록 표(`st.dataframe`)가 화면 폭에 맞게 렌더링되도록 구성하라."
- **AI 생성 결과 (요지)**:  
  `_read_csv_with_cp949_fallback()`에서 `UnicodeDecodeError` 예외 블록 내부에만 `uploaded_file.seek(0)`을 배치하고, 상세 표 출력부에는 `st.dataframe(df_filtered, use_container_width=True)`를 생성함.
- **발견한 문제**:  
  1. **[스트림 포인터 가정 결함]**: 최초 `pd.read_csv(uploaded_file)` 직전에는 `seek(0)`이 없어, 앞선 검사나 재사용으로 파일 포인터가 `0`이 아닌 상태의 스트림이 전달되면 첫 읽기 단계에서 빈 읽기·파싱 오류가 날 수 있음.
  2. **[구버전/폐기 API 경고]**: 설치된 `streamlit 1.67.0` 환경에서 `AppTest`로 실행하자 `Please replace use_container_width with width. use_container_width will be removed after 2025-12-31.` 폐기 안내 로그가 2회 출력됨(강의노트 30p 'AI 코드에서 구버전 API 의심' 체크 항목 해당).
- **수정 내역 (`app.py` `_read_csv_with_cp949_fallback` 및 `st.dataframe` 호출부)**:  
  1. `_read_csv_with_cp949_fallback()` 진입 시점에도 `uploaded_file.seek(0)`을 먼저 호출해 스트림 시작 위치를 항상 보장하도록 수정.
  2. 폐기 예정 인자 `use_container_width=True`를 제거해 `st.dataframe(df_filtered)`로 정리(`streamlit>=1.30` 하위 호환성 유지).
- **검증**:  
  - `AppTest` 재실행 결과 `Streamlit deprecation warnings found: 0`, 미업로드 중단 / `cp949` 14행 복원 / 필터 Rerun 캐시 재사용 / 필수 컬럼 누락 방어 5개 시나리오 전원 통과.
  - `python -m pytest -q`: `126 passed` 확인.
- **판단 메모**:  
  AI는 학습 시점의 관성으로 `use_container_width=True` 같은 폐기 예정 API를 습관적으로 넣으며, `seek(0)` 역시 예외 분기에만 두고 최초 호출 전 선행 조건을 빠뜨리기 쉬움. 실제 실행 환경(Streamlit 1.67)에서 로그와 경계 조건을 직접 돌려 확인한 뒤 커밋하는 절차가 유효함을 확인함.
