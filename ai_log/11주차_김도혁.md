### 2. AI 생성 코드 (발췌)

최초 생성된 `backend.py`의 `filter_analyses`다.

```python
def filter_analyses(
    df_clean: pd.DataFrame,
    min_score: float = 0.0,
    selected_tag: str = ALL_TAGS,
) -> pd.DataFrame:
    """최소 점수와 선택 태그 조건을 만족하는 행만 복사해 반환합니다."""
    result = df_clean[df_clean["final_score"] >= min_score]
    if selected_tag != ALL_TAGS:
        has_tag = [
            isinstance(tags, (list, tuple)) and selected_tag in tags
            for tags in result["tags"].tolist()
        ]
        result = result[has_tag]
    return result.copy()
```

함께 생성된 빈 입력 테스트는 `.empty`만 확인했다.

### 3. 발견한 문제 및 원인 분석

발견 경위: 생성된 코드를 그대로 커밋하지 않고 AI에 구현 상황 점검을 요청했다. 점검 보고에서 아래 문제가 재현 결과와 함께 나왔고, 이를 수정 대상으로 정했다.

보고만 믿지 않고 직접 재현하기로 하고, 수정 전 함수와 현재 함수를 같은 입력으로 비교하는 재현 스크립트 `ai_log/week11_task1_evidence/reproduce_filter_bug.py`를 만들었다. 실행 결과는 5번에 있다.

본인 직접 실행 확인: 2026-11-16에 터미널에서 직접 실행했다. 수정 전 함수는 "점수 10.0 + 태그 선택"과 "헤더만 있는 입력 + 태그 선택"에서 `(0, 0)`을 반환했고, 현재 함수는 네 경우 모두 열 4개를 유지했다.

- 증상: 점수 조건에서 남는 행이 0개이고 `selected_tag`가 `"전체"`가 아니면 반환값의 모양이 `(0, 0)`이 된다. 필수 열 4개가 모두 사라진다.
- 재현 조건:
  - 최소 점수 10.0 + 태그 선택 → `(0, 0)`
  - 헤더만 있는 CSV + 태그 선택 → `(0, 0)`
  - 최소 점수 10.0 + `"전체"` → `(0, 4)` (정상)
- 원인: `result[has_tag]`에서 `has_tag`가 빈 리스트가 되면 pandas가 불리언 마스크가 아니라 "열 이름 0개 선택"으로 해석한다.
- 영향: Task 3의 `app.py`가 이 반환값을 `st.dataframe`에 넘기므로, 슬라이더를 끝까지 올리고 태그를 고르면 표의 열 헤더가 사라질 수 있다. KPI와 차트는 0으로 정상 계산된다. 같은 "결과 0건"인데 `"전체"`일 때와 태그를 골랐을 때 반환 형태가 달라 계약이 일관되지 않는다.
- 테스트가 놓친 이유: `(0, 0)` DataFrame도 `.empty`가 참이라서 `.empty`만 보는 검사는 통과한다.

같은 점검에서 나온 나머지 세 가지는 사례 2에서 다룬다.

### 3. 발견한 문제 및 원인 분석

| 입력 | 수정 전 동작 | 원인 |
|---|---|---|
| 데이터에 `"전체"`라는 태그가 있음 | 선택지가 `["전체", ..., "전체"]`로 중복 | 예약어 `"전체"`를 실제 태그 집합에서 빼지 않음 |
