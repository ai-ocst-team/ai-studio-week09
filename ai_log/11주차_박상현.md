## 사례 2. 환경 파일 제외 누락과 감사 범위의 구분

### 1. 초기 프롬프트

사례 1에 인용한 동일 요청의 “보안 점검” 부분을 이어서 수행했다. 별도의 사용자 프롬프트나 독립적인 제품 리팩터링 작업이 있었던 것으로 기록하지 않는다.

### 2. AI 생성 코드·설정

기존 제외 규칙에 `.env.*` 한 줄을 추가하고 감사 스크립트를 작성했다. 스크립트는 Git 추적·이력·제외 규칙 검사, 코드 구조 점검, 실제 CSV 함수 검증 및 pytest 결과를 출력한다.

```gitignore
.env
.env.*
*.local
```

### 3. 발견한 문제·판단

수정 전 `git check-ignore -v`에서 `.env`는 제외됐으나 `.env.production`은 출력되지 않아 제외되지 않는 것을 Codex가 확인했다. 또한 기존 보안 문서는 10주차 기록으로, 이를 11주차 전체 확인 결과로 그대로 재사용하면 검사 범위를 과장하게 된다. `.env` 파일명 이력 0건과 모든 파일 속 비밀값 부재는 다른 주장이다.

### 4. 수정·보완 내역

환경별 파일도 제외하도록 `.env.*`를 추가했다. 기존 보안 기록을 보존하고 11주차 S1~S10 범위·근거·한계를 추가했다. 자격증명 후보가 있을 때 원문 대신 경로·줄만 출력하도록 감사 코드를 구성했다. 전체 과거 키 내용 검사·스크린샷 OCR·외부 AI 전송 이력은 검사하지 않았다고 명시했다.

### 5. 검증 결과·Git 기록

- fetch 이후 전체 로컬 ref 기준 `.env*` 파일명 이력 0건, 현재 추적 파일 0건, shallow clone 아님.
- 루트·중첩 `.env`와 `.env.production`, `.env.local`, 캐시·가상환경·local 파일 등 검사 경로 7개 모두 제외됨.
- UI 가공 호출 및 backend Streamlit import 미발견. 검수한 CSV 경로 코드에서 제한된 자격증명·외부 호출 패턴 후보 0건. 무제한 보안 감사 결과로 해석하지 않는다.
- 자동 검사와 전체 pytest는 사례 1의 같은 실행이며 두 번 실행했다고 집계하지 않는다. 감사 종료 코드 0.
- 커밋·push: 사용자가 수행하기로 했으며 아직 미실행. 검토 후 실제 커밋 해시를 확인할 수 있다.
