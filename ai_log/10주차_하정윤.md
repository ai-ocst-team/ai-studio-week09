## [2026-11-09] 파이프라인 Mock 연동 누락 및 무차별 예외 처리 리팩터링 (담당: 하정윤)
- **대상 모듈**: `pipeline.py` / **관련 커밋**: `619cd74` → `e5b4325`
- **품질 관점**: [효율성 · 보안/안정성 · 데이터 정확성]
- **초기 프롬프트 (요지)**:  
  "9주차 모듈들을 연결하는 `pipeline.py`를 작성하고, `use_mock` 플래그 지원 및 개별 이미지 오류 발생 시 파이프라인 전체가 멈추지 않도록 예외 처리를 추가하라."
- **AI 생성 결과 (요지)**:  
  `run_pipeline` 함수 시그니처에 `use_mock: bool = True` 매개변수를 선언했으나 내부 VLM 호출부에는 전달하지 않았으며, 이미지 순회 루프 전체를 `except Exception as exc:`로 감싸 무조건 스킵하고, VLM의 aesthetic_tags를 단순히 평탄화만 수행하는 코드를 작성해 옴.
- **발견한 문제 (3대 품질 관점 리뷰)**:  
  1. **[효율/계약 결함]**: `use_mock` 매개변수가 선언만 되고 내부 VLM 클라이언트에 전달되지 않아, 사용자가 CLI에서 플래그를 변경해도 Mock/Real 전환이 전혀 동작하지 않는 Dead Parameter 결함 식별.
  2. **[안정성/가독성 결함]**: `except Exception:`으로 무차별 포괄(catch-all) 처리하여, 손상 이미지뿐만 아니라 오타나 모듈 간 계약 위반(`TypeError`, `KeyError`) 등 즉시 잡아야 할 런타임 버그까지 경고만 남기고 삼켜버리는 위험 확인 (교수님 가이드라인 4장 '예외 삼킴 방지' 위배).
  3. **[정확성 결함]**: VLM 응답에서 카테고리 간 중복 태그가 발생할 경우, 중복 필터링 없이 리스트에 추가되어 `aggregate_photo_insights`의 통계 신뢰성을 왜곡할 수 있는 문제 확인.
- **수정 내역 (코드 내 `[수정 1~3]` 주석 반영)**:  
  - **`[수정 1]`**: `os.environ["USE_MOCK"] = "true" if use_mock else "false"`를 명시하여 시스템 환경변수와 동기화, 하위 VLM 클라이언트가 모드를 정확히 감지하도록 수정.
  - **`[수정 2]`**: 예외 처리 범위를 `except (UnidentifiedImageError, OSError, ValueError) as exc:`로 한정하여, 손상 파일이나 파싱 불가 데이터만 안전하게 스킵하고 치명적 버그는 조기 감지되도록 방어벽 강화.
  - **`[수정 3]`**: `unique_tags = list(dict.fromkeys(flat_tags))`를 적용하여 입력 순서를 유지하면서 중복 태그를 완전히 제거.
- **검증**:  
  - `python main.py --image-dir sample_images` 실행 결과 정상 통과 확인.
  - 유효하지 않은 디렉토리 주입 시 `ValueError`가 정상 전파됨을 검증.
  - 커밋 해시: `e5b4325` (`refactor(pipeline): AI코드 수정 | USE_MOCK 동기화, 제외조건 구체화, 중복태그방지`)
- **판단 메모**:  
  AI가 생성한 코드가 겉으로 에러 없이 돌아간다고 해서 완벽한 것이 아님. 특히 `except Exception:` 같은 안티패턴은 시스템의 잠재적 결함을 은폐하므로, 건너뛸 예외 타입을 명확히 한정하고 매개변수가 실제로 제어 흐름에 반영되는지 엄격히 검증하는 인간 엔지니어의 통제가 필수적임을 체득함.

## [2026-11-09] Windows 환경 CLI cp949 인코딩 크래시 해결 및 크로스 플랫폼 표준화 (담당: 하정윤)
- **대상 모듈**: `main.py` / **관련 커밋**: `da35832` → `619cd74`
- **품질 관점**: [안정성/호환성 · 가독성]
- **초기 프롬프트 (요지)**:  
  "통합 파이프라인을 CLI 터미널 환경에서 실행하고, 진행 상태와 최종 통계 리포트를 시각적으로 확인할 수 있는 `main.py` 스크립트를 작성하라."
- **AI 생성 결과 (요지)**:  
  CLI 출력의 시각적 가독성을 높이기 위해 `📸`, `✅`, `❌`, `💾` 등의 유니코드 이모지를 다수 포함한 콘솔 출력 코드를 작성해 옴.
- **발견한 문제**:  
  - **[안정성 및 환경 종속적 런타임 크래시]**: Windows PowerShell 환경에서 실행하자마자 기본 콘솔 인코딩(`cp949`)이 유니코드 이모지(`\U0001f4f8`)를 인코딩하지 못하여, 프로그램 시작과 동시에 `UnicodeEncodeError: 'cp949' codec can't encode character in position 0` 예외를 뿜으며 즉시 프로세스가 비정상 종료(Crash)되는 치명적 결함 발생.
- **수정 내역 (`main.py` 코드 16~22줄 및 출력부)**:  
  1. `sys.stdout.reconfigure(encoding="utf-8")` 및 `sys.stderr.reconfigure(encoding="utf-8")` 방어 코드를 스크립트 최상단에 배치하여 터미널 표준 입출력을 utf-8로 강제 재구성.
  2. 환경(OS/터미널 인코딩)에 따라 깨지거나 런타임 오류를 유발할 수 있는 비표준 이모지를 크로스 플랫폼 호환 표준 텍스트 기호(`[아트서강]`, `>>`, `[SUCCESS]`, `[ERROR]`, `[INFO]`)로 전면 교체.
- **검증**:  
  - Windows 터미널에서 `python main.py --image-dir sample_images --hint "배경 중심" --output results/output.json` 실행 시 인코딩 오류 없이 한글 안내문과 최종 JSON 파일이 정상 출력 및 저장됨을 확인.
  - 커밋 해시: `619cd74` (`feat:파이프라인 구현`), 머지 커밋: `cef6956`
- **판단 메모**:  
  AI는 운영체제별 터미널 환경(Windows cp949 vs Linux utf-8)의 차이를 스스로 고려하지 않고 시각적 화려함(이모지)에 치중한 코드를 생성하는 경향이 있음. 실무 CLI 도구 개발 시 크로스 플랫폼 인코딩 호환성을 사전에 방어하고 표준 텍스트 포맷을 채택하는 것이 안정성 관점에서 훨씬 중요함을 배움.
