# 9주차 AI·데이터 보안 체크리스트

최초 점검일: 2026-11-02 / 제출 상태 갱신: 2026-11-03. 대상: 이 개인 담당 모듈 폴더의 코드·테스트·문서·보존 증빙입니다. 5주차에 사용한 S1~S10 항목을 기준으로 작성했습니다. 팀 저장소 전체나 외부 서비스의 기록은 점검 대상이 아닙니다.

| 번호 | 점검 항목 | 상태 및 근거 |
|---|---|---|
| S1 | 제출물에 실존 인물의 실명·전화번호·이메일 등 PII가 없는가? | **부분 충족**. 테스트는 가상 데이터이며 실제 사진·고객 데이터가 없습니다. 문서의 담당자 이름과 실행 로그의 로컬 사용자 경로는 남아 있어 전체가 익명이라고 표시하지 않습니다. |
| S2 | 외부 AI에 기업 기밀·타인 코드·PII를 입력하지 않았는가? | **확인 범위 명시**. 이번 함수 작업은 팀 설계 내용·가상 입력·AI 작성 코드와 테스트를 이용했습니다. 기업 기밀·실제 고객 데이터·실제 API 키를 사용하지 않았습니다. 팀 문서와 사용자 화면을 AI와 검토했으므로 아무 외부 자료도 제공하지 않았다고 주장하지 않습니다. 이번 작업 세션의 대화 JSON을 확보하여 요청과 도구 기록을 확인했습니다. |
| S3 | 외부 데이터의 출처·라이선스 확인 및 비식별 처리를 했는가? | **해당 없음 — 외부 실데이터 미사용**. 직접 준비한 가상 테스트 입력을 사용했습니다. 팀 설계 문서를 참고했으며 별도 데이터셋을 수집·재배포하지 않았습니다. |
| S4 | 소스에 API 키·비밀번호를 하드코딩하지 않았는가? | **확인**. 함수는 외부 API·DB 연결을 사용하지 않습니다. 텍스트 파일의 제한된 자격 증명 패턴 점검 결과는 별도 증빙에 기록했습니다. 패턴 검사만으로 모든 비밀 정보의 부재를 보증하지는 않습니다. |
| S5 | `.env` 제외 규칙과 Git 미추적 상태를 확인했는가? | **일부 확인 / 적용 후 재확인 필요**. 개인 폴더 제외 규칙과 환경 파일 부재를 확인했습니다. 팀 저장소 검토 사본에서도 `.env`, `.venv/`, `__pycache__/` 제외 규칙 및 해당 파일 미추적을 확인했습니다. 개인 파일을 팀 저장소 사본에 반영했습니다. `.env.*`까지 제외하는 개인 폴더의 추가 규칙은 이번 문서 커밋에 포함할 예정입니다. |
| S6 | 커밋 이력의 키 노출 여부를 확인했는가? | **미확인**. 개인 로컬 커밋 2개는 완료했지만 제출 대상 저장소 전체 이력의 비밀 값 검사는 하지 않았습니다. 과거 이력까지 안전하다고 판정하지 않습니다. |
| S7 | 비밀 값을 출력·로그·스크린샷에 노출하지 않았는가? | **확인 — 확보된 증빙 범위**. 로그는 테스트 결과이고 완료 화면은 구현 요약입니다. 실제 API 키를 사용하지 않았습니다. 사용자 로컬 경로는 실행 증빙에 포함됩니다. |
| S8 | AI 사용 내역을 기록·첨부했는가? | **대화·작업 기록 및 로컬 커밋 확인**. `prompt_log.md`에 프롬프트 전문, Copilot 최초 구현, OpenAI Codex 준비·검토·후속 오류 수정·테스트·문서 작성을 구분했습니다. 실제 대화 JSON을 보관하고 준비 프롬프트와 일치를 확인했습니다. 실제 커밋 `be8c457`, `54cc951`을 기록했습니다. 문서 커밋·업로드는 대기 중입니다. |
| S9 | LLM 입력 검증과 출력 형식 확인을 적용했는가? | **LLM 호출에는 해당 없음**. 이 함수는 LLM을 호출하지 않습니다. DataFrame 타입·필수 열·점수·날짜를 검증합니다. 팀 VLM 응답 검증은 다른 담당 함수의 책임입니다. |
| S10 | 시스템 프롬프트에 비밀 정보가 없는가? | **실행 시 시스템 프롬프트 없음**. 개발용 Copilot 준비 프롬프트에는 명세와 가상 입력만 있으며 비밀 값이 없습니다. |

## 점검 근거와 남은 확인

- [과거 기록 점검 결과](evidence/records_verification.json): 보존 원본 해시, 현재 구현·테스트·준비 프롬프트 일치 여부, 검사한 텍스트 파일 수와 비밀 값 패턴 후보 위치. 후보 원문은 출력하지 않습니다.
- [검토 기록](evidence/code_review.txt): 함수 내부의 외부 통신·DB 접근·동적 코드 실행 부재 등을 검토했습니다.
- 이번에는 코드·문서의 로컬 점검만 수행했습니다. 업로드 전에 실제 대상 저장소의 추적 파일과 커밋 이력을 확인해야 합니다.
- 자동 패턴 점검은 이미지 OCR·삭제된 파일·외부 계정 기록까지 검사하지 않습니다. 완료 화면은 제공된 이미지를 읽은 범위에서 확인했습니다.


## 수정 후 점검

- 빈 입력 조건 수정과 회귀 테스트는 가상 DataFrame을 사용합니다. 새 외부 통신이나 자격 증명 의존성을 추가하지 않았습니다.
- 로컬 전체 테스트 33개 통과 및 원본 보존 상태는 각 실행 당시의 출력에 연결했습니다. 저장소 폴더 검증은 `pytest_repository_check.txt`를 참조합니다.
- 최초 검토 시 팀 사본의 HEAD는 `2bf3f19`였으며, 현재 개인 브랜치 HEAD는 `54cc951`입니다. 이 사본의 파일 목록·제외 규칙을 확인했지만 전체 이력의 비밀 값 검사나 팀 전원 교차 확인을 수행한 것은 아닙니다.
- 팀원 양식에 맞춰 파일명을 SECURITY_CHECKLIST.md로 정리했습니다. 개인 로컬 커밋은 사용자가 실행했으며 아직 push하지 않았습니다.

과거 검증 JSON은 당시 상태의 기록이며 이후 문서·증빙 헤더 편집으로 현재 해시와 다를 수 있습니다. 이를 현재 전체 파일 검증 결과로 사용하지 않습니다. [증빙 안내](evidence/README.md)를 참조합니다.
