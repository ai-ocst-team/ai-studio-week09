## 4단계: 코드 리딩·검증 및 수정

### 4.1 발견한 결함

기존 조건은 `df_raw.empty and len(df_raw.columns) == 0`이었습니다. pandas의 `empty`는 한 축의 길이가 0이어도 참이므로, 행 인덱스가 있지만 열이 없는 표도 특별 허용 대상인 완전히 빈 표로 오인했습니다.

| 구분 | 내용 |
|---|---|
| 재현 입력 | `pd.DataFrame(index=[101, 102])` |
| 명세의 기대 | 필수 열 누락 ValueError |
| 수정 전 동작 | 행 인덱스를 버리고 `(0, 4)` 크기의 표준 빈 표 반환 |
| 기존 테스트의 공백 | `(0, 0)`과 일부 필수 열이 빠진 표는 검사했지만 `(2, 0)`은 검사하지 않음 |
| 영향 | 잘못된 입력 구조가 정상적인 “데이터 없음” 결과로 바뀌어 오류 확인이 어려워짐 |

### 4.2 수정 내용과 판단 근거

먼저 회귀 테스트를 추가하여 수정 전 구현에서 `DID NOT RAISE ValueError`로 실패하는 것을 확인했습니다. 그다음 특별 허용 조건을 아래처럼 바꾸었습니다.

```python
# 수정 전

# 수정 후: 행과 열이 모두 없는 경우만 허용

```

행 인덱스만 있는 표는 이제 기존 필수 열 검사로 넘어가 ValueError를 발생시킵니다. 정상적인 빈 표의 반환, 점수·날짜 처리 및 함수 시그니처는 유지했습니다. 추가 테스트는 네 필수 열이 오류 메시지에 포함되는지와 입력이 변경되지 않는지도 확인합니다.

증빙 폴더의 과거 테스트 사본이 현재 테스트에 중복 수집되지 않도록 `evidence/conftest.py`에서 원본 보존 폴더만 제외했습니다. 현재 테스트는 모두 실행됩니다. 전체 변경은 [수정 diff](evidence/review_fix.diff)와 해당 설정 파일에서 확인할 수 있습니다.
